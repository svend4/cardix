# Karten-Projekt

Монорепозиторий: одно ядро и независимые кластеры для разных видов услуг.

Идея ядра: **карточка — это стабильный номер позиции**. Одна и та же запись каталога
печатается на бумаге, показывается на экране, кодируется в QR и читается симулятором.
Бумага работает офлайн, экран и QR — когда есть сеть и устройство.

## Структура

| Папка | Что внутри | Статус |
|---|---|---|
| `00-kern` | Формат каталога, правила Leichte Sprache, схема QR, общие принципы | спецификация v0.1 |
| `10-senioren-dienste` | Карточки услуг для пожилых: печать + интерактивная страница | прототип, не проверен на людях |
| `20-essen-vending` | Заказ еды, вендинг, ячейки выдачи, курьеры-велосипедисты | идея + выводы модели |
| `30-spiele-comics` | Карточные игры, комиксы, бумажные куклы и «бутерброды» из слоёв | идея |
| `40-projekt-karten` | Карточки задач, конвейеры, спецификации, Zettelkasten | идея |
| `50-digitaler-zwilling` | Симулятор: заказы, роботы, курьеры, сбои | модель v0.2 |
| `60-reise-sprachkarten` | Разговорник для поездок: картинка + фраза, офлайн | идея |

## Правила монорепозитория

1. **Ядро не знает о кластерах.** Кластер импортирует ядро, ядро не импортирует кластер.
2. **Кластер не меняет ядро.** Если кластеру нужно новое поле — сначала решение в `00-kern/DECISIONS.md`,
   потом новая минорная версия формата.
3. **Расширения — через пространство имён.** Свои поля кластер пишет в `ext.<кластер>`,
   например `ext.vending.slot`. Чужие расширения игнорируются, а не ломают чтение.
4. **Один каталог — много представлений.** Печать, HTML, QR и симулятор читают один и тот же файл.
   Если данные расходятся — ошибка, а не «две правды».
5. **Номер карточки никогда не переиспользуется.** Удалённая позиция помечается `retired`, номер остаётся занятым.
   Иначе старые напечатанные карточки начнут значить другое.
6. **Никаких персональных данных на карточке и в QR.** Только код позиции. Кто, где, здоровье — вне карточки.
7. **Offline-first.** Каждая функция должна иметь бумажный или локальный запасной путь.
8. **Zero dependencies где возможно.** Python stdlib, чистый HTML/JS без сборки, Apache-2.0.

## Порядок развития

1. `10-senioren-dienste`: проверка шести карточек на 3–5 людях.
2. `00-kern`: зафиксировать формат каталога по итогам проверки.
3. QR с кодом позиции → интерактивная страница читает тот же каталог.
4. `50-digitaler-zwilling` переходит на общий каталог.
5. `20-essen-vending`: бумажный пилот на 10 позиций.
6. Остальные кластеры — по мере готовности ядра.
