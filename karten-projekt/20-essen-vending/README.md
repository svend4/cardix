# 20-essen-vending — заказ еды, вендинг, ячейки выдачи

## Идея
Готовая упакованная еда из вендинговых автоматов в закрытом помещении. Роботы загружают ячейки,
курьеры (в том числе велосипедисты) забирают набор по одноразовому коду, как в Packstation.
Две зоны: внутри роботы, снаружи люди. Граница — ячейка выдачи.

## Расширения ядра (`ext.vending`)
- `slot` — номер ячейки автомата;
- `allergens` — список аллергенов (дублируется в `flags`, чтобы всегда показывался);
- `shelf_life_days` — срок годности;
- `cold` — нужна ли холодильная цепь (для старта: false).

## Шестерёнки для рационализации
1. **Единый каталог**: меню, печать, ячейка и склад читают один номер.
2. **Модификаторы — отдельные маленькие карты** («без лука», «двойная»), связи `alt` / `excludes`.
3. **Сверка на выдаче**: второй скан сравнивает собранное с заказанным до передачи курьеру.
4. **Запасной путь**: распечатанный код выдачи, если телефон сел.
5. **Защита по цене ошибки**: подписанный код (HMAC) только для ячеек и денег, не для меню.

## Пилот — первые 10 позиций (без холода)
Вода, вода газированная, чай, сок, печенье, сухарики, яблоко, батончик, орехи, шоколад.
Орехи и шоколад — нарочно, чтобы проверить метки аллергенов.

## Выводы модели (см. `50-digitaler-zwilling`) — допущения, не факты
- Заказ раз в 12 мин: одного курьера хватает; второй по вызову снижает ожидание примерно вдвое.
- Час пик, заказ раз в 6 мин: один курьер не справляется; нужны двое на смене.
- Порог вызова второго курьера: 3 заказа в очереди (2 не лучше).
- Ожидание пакета 5–10 мин даёт небольшой выигрыш и меньше поездок.

## Готовые компоненты рынка (проверить перед выбором)
Платёжные и телеметрические модули для автоматов (класс Nayax / Cantaloupe), протокол MDB
между платёжным модулем и контроллером. Писать самим только «клей»: каталог, код выдачи, веб-страницу.
